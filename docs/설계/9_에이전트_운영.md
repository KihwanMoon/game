# 에이전트 운영

> 지속 운영에 어떤 에이전트가 필요하고, 어떻게 붙이는가.
>
> **정본은 코드다.** 여기 적힌 것과 라우트가 갈리면 라우트가 맞다.

---

## 0. 왜 에이전트인가 — 오늘의 근거

이 문서는 상상이 아니라 **하루치 실측**에서 나왔다. 2026-09-04~05 에 손으로 찾은
결함들이다. 전부 **아무도 안 볼 때 조용히 돌고 있었고**, 사람이 DB 를 뒤져서야 드러났다.

| 무엇 | 얼마나 | 어떻게 드러났나 |
|:--|:--|:--|
| 정비 규칙 7행 중 **2행이 한 번도 안 돎** | 무기·방패를 영영 안 바꿈 | 봇 로그를 눈으로 훑다가 |
| 정비가 **사람에게 한 번도 안 돎** | 이기고 그만두면 티켓이 안 닫힘 | 사용자 신고 |
| 봇이 경매에서 **무기를 영영 안 삼** | 같은 절이 두 곳에 | 위 건을 고치다가 |
| 도플갱어 자리 다섯이 **하루 만에 굳음** | 1,170판이 버려짐 | 「업데이트가 안 된다」 |
| 그림자가 **원본 봇보다 약함** | 공격 1/3, 방어 1/6 | 「더 강하게」 물어보다가 |
| 그림자 전부가 **같은 규칙표**로 싸움 | 배선 자체가 없음 | 위와 같은 자리 |
| 꽉 찬 가방에서 갈아 끼우면 **판 정산이 통째로 날아감** | `/api/run` 500 | 봇 로그의 500 하나 |
| **최고 층이 1 에서 안 움직임** | 층 보너스 슬롯이 아무에게도 안 붙음 | 「봇이 계속 1층이야」 |
| G1 보고서가 **봇을 셈** | 판정이 통과↔미달로 뒤집힘 | 테스터 부르기 직전에 |

**공통점은 하나다.** 코드는 돌았고, 검사는 통과했고, 화면은 멀쩡했다. 그런데 **세계가
틀린 상태로 돌고 있었다.** 단위 검사가 잡는 것은 「이 함수가 맞는가」이고, 이것들은
「지금 세계가 말이 되는가」다 — 그 질문을 계속 묻는 것이 없었다.

**그래서 첫 번째 에이전트는 콘텐츠를 만드는 것이 아니라 세계를 지켜보는 것이다.**

## 1. 다섯 갈래 — 넷은 일하고 하나는 문을 지킨다

| 갈래 | 무엇 | 언제 |
|:--|:--|:--|
| **A. 지켜본다** | 세계가 말이 되는가를 주기적으로 묻는다 | **지금** |
| **B. 잰다** | G1·G2·밸런스 판정 자료를 낸다 | 지금 (도구는 있다) |
| **C. 만든다** | 밸런스·시나리오·아이템·맵·몬스터 초안 | 세 구멍을 막은 뒤 |
| **D. 응대한다** | CS — 문의 분류, 계정 조사, 개입 제안 | 사용자가 늘면 |
| **E. 문을 지킨다** | 배포봇 — 나머지가 만든 것을 검토하고 사람에게 올린다 | **C 와 함께** |

순서에 이유가 있다. **A 없이 C 를 붙이면 세계가 더 빨리 틀려진다** — 오늘 찾은 결함들이
사람 손으로 만든 것 위에서 났는데, 만드는 속도만 올리면 틀린 상태가 쌓이는 속도도 오른다.

**E 는 C 와 짝이다.** 만드는 에이전트가 없으면 지킬 문도 없고, 만드는 에이전트가 있는데
문이 없으면 검토 없이 세계가 바뀐다.

## 2. 붙이는 법 — 봇 러너가 이미 그 패턴이다

새 아키텍처가 필요 없다. `scripts/run_bots.py` 가 이미 에이전트의 형태로 돌고 있고,
그 파일의 첫 문단이 규약을 정해 뒀다.

> **라우트를 그대로 탄다.** `game_net` 안에서 백엔드에 HTTP 로 붙어 순서대로 부른다.
> 서비스 계층을 직접 부르면 티켓 1회용·코어버전 대조·정비 같은 라우트 규율을 우회하게
> 되고, 그러면 봇의 런은 「진짜 경로가 도는지」를 더 이상 증명하지 못한다.

### 규약 넷

1. **별도 프로세스.** compose 서비스 하나. 백엔드와 배포 주기를 나누지 않는다 —
   `core_version` 정합성이 단일 배포에 기대고 있다 (§6).
2. **HTTP 라우트만.** `game.app.services` 를 직접 import 하지 않는다. 에이전트가 우회하는
   규율은 사람도 우회할 수 있게 된다.
3. **전용 계정.** 에이전트마다 계정 하나. 무엇을 했는지가 `admin_action` 에 남고,
   사고가 났을 때 어느 에이전트인지 바로 짚인다.
4. **읽기는 자유, 쓰기는 좁게.** 아래 §3 의 권한 등급이 이것을 강제해야 한다.

### 왜 MSA 가 아닌가

결정론 코어는 밸런스·블록·방·적·규칙표를 **한 프로세스 안에서** 들고 재시뮬한다.
네트워크 너머로 가르면 스냅숏 일관성을 손으로 관리해야 하고, 조금만 어긋나면
`mismatch` 가 나서 **정상 플레이어가 반려된다.** 코어는 **복제**하되 **분해하지 않는다.**

MSA 가 필요해지는 조건은 기술이 아니라 조직이다 — 팀이 여럿이 되어 배포 주기를 나눠야
할 때. 그때까지는 **모듈러 모놀리스 + 주변부 분리**가 맞고, 이 저장소는 이미 그 모양이다.

## 3. 먼저 막아야 하는 구멍 셋

에이전트를 붙이기 전에 닫아야 한다. 셋 다 오늘 확인한 것이다.

### 3.1 권한이 이분법이다 🔴

`account.is_admin` 불리언 하나가 전부다. 관리자면 **콘텐츠 발행·아이템 지급·아이템 회수·
카탈로그 편집·몬스터 레벨 변경**을 전부 할 수 있다.

에이전트마다 할 수 있는 일이 달라야 한다 — CS 에이전트가 콘텐츠를 발행할 수 있으면 안
되고, 밸런스 에이전트가 아이템을 지급할 수 있으면 안 된다. **지금 구조로는 못 나눈다.**

필요한 등급(안):

| 등급 | 할 수 있는 것 |
|:--|:--|
| `observer` | 읽기 전량. 쓰기 없음 |
| `author` | 콘텐츠 **초안**. 발행 불가 |
| `operator` | 계정 개입(아이템 회수·봇 멈춤). 콘텐츠 불가 |
| `owner` | 전부. **사람만** |

**발행은 어느 등급도 안 준다.** 사람이 누른다 — 그 경계는 이미 코드가 정해 뒀다
(§4.1).

### 3.2 아이템만 초안을 안 거친다 🔴

초안 가능한 자산은 다섯이다: `skills · blocks · balance · rooms · enemies`.
**아이템은 없다.** 카탈로그 정본이 DB 라서 `/admin/catalog/edit`·`/catalog/item`·
`/catalog/retire` 가 **즉시 반영**한다 — 초안도, 검증도, 세대도 안 거친다.

아이템 에이전트를 붙이면 **검토 없이 바로 세계가 바뀐다.** 다른 넷은 사람이 발행을
눌러야 하는데 아이템만 문이 열려 있다.

### 3.3 발행이 진행 중이던 판을 반려시킨다 🟠

```python
mismatch = check_submission_version(request.core_version, ticket.core_version)
```

클라이언트를 **티켓과** 대조한다 — 서버와는 안 한다. 그래서 검사는 통과하는데,
`evaluate_submission(get_context(), …)` 이 **지금 컨텍스트로** 재시뮬한다.

1. 티켓 발급 (코어 버전 X) → 사람이 판을 시작
2. 발행 → 서버는 Y
3. 제출: `request X == ticket X` → 검사 통과
4. 재시뮬은 Y, 브라우저는 X → 결과가 갈림 → **`mismatch`**

발행 라우트는 열린 티켓을 안 건드린다. 그 사람은 아무 잘못 없이 판을 잃는다.

**지금은 발행이 드물어서 안 드러난다.** 에이전트를 붙이면 발행이 잦아지는 것이 요점이라
이것이 상시가 된다 — 결정 #47 이 「불일치의 원인은 변조·버전 시차·우리 버그 셋」이라
적어 둔 것 중 **두 번째가 대량 생산된다.**

고르는 길 둘:
- **(a) 발행이 열린 티켓을 만료시킨다.** 간단하고, 그 순간 놀던 사람이 판을 잃는다.
- **(b) 티켓의 코어 버전으로 재시뮬한다.** 정석이지만 **옛 팩을 보관**해야 한다 —
  `content_published` 가 이미 세대별로 쌓이므로 자리는 있다.

## 4. 에이전트별 명세

### 4.1 세계 지킴이 (A) — 첫 번째로 붙인다

**무엇을 묻는가.** 전부 오늘 손으로 돌린 질의다.

| 지표 | 정상 | 오늘 실측 |
|:--|:--|:--|
| 정비 행별 발동률 | 모든 행이 가끔은 돈다 | **2행이 0** |
| 정비가 도는 계정 비율 | 판을 돈 계정 대부분 | 이기고 그만두면 **0** |
| 봇 가방 포화율 | 낮게 유지 | **17~19/20 고착** |
| 도플갱어 보토 회전 | 하루에 몇 번은 바뀐다 | **이틀 정지** |
| 경매 체결률 | 6시간 창 뒤 팔린다 | 무기류 **구조적 0** |
| `mismatch` 비율 | 배포 직후 말고는 0 에 가깝다 | — |
| `/api/run` 5xx | 0 | **간헐 발생** |
| 최고 층 분포 | 도달 기록과 일치 | **전부 1 로 고정** |

**무엇을 하는가.** **아무것도 안 고친다.** 이상을 적어 사람에게 올린다 — 자동으로
고치면 「왜 그랬는지」가 사라지고, 오늘 찾은 결함들은 전부 **원인이 이유였지 증상이
아니었다.**

**권한**: `observer`.

### 4.2 판정 에이전트 (B)

`scripts/report_g1.py` 가 이미 있다(봇 필터 포함). 여기에 붙일 것은 **주기와 보관**이다 —
매일 돌려 기록을 남기면 「언제부터 나빠졌는가」에 답할 수 있다. 지금은 그때그때 돌린다.

**권한**: `observer`.

### 4.3 콘텐츠 에이전트 (C) — 구멍 셋을 막은 뒤

밸런스 · 시나리오 · 몬스터 · 맵 · 아이템. 전부 **초안까지만**.

경로는 이미 있고 검증이 진짜다 — `check_loads` 가 임시 파일에 쓴 뒤 **코어가 쓰는
그 로더**를 부른다. 못 읽는 절은 그 자리에서 막힌다.

**두 가지를 지킨다.**
- **발행은 사람이 누른다.** 자동으로 반영되면 순위표 시즌이 아무도 모르게 갈린다.
- **한 번에 하나씩 낸다.** 세대는 발행 시점에 한 번 받으므로, 여러 자산을 함께 고치고
  한 번에 내는 것이 이 파이프라인의 뜻이다.

**권한**: `author`.

**시나리오는 자산이 없다.** 튜토리얼 스테이지(`tutorial.json`)와 방 배치가 그 재료인데,
튜토리얼은 초안 목록에 없다. 시나리오 에이전트를 붙이려면 자산 하나를 먼저 정해야 한다.

### 4.4 CS 에이전트 (D) — 사용자가 늘면

읽기가 대부분이다 — 계정·런·제출·아이템 이력 조회. 쓰기는 개입이고
`admin_action` 테이블이 이미 그것을 받는다.

**성격이 다르다.** 읽기 비중이 압도적이라 **읽기 복제본 위의 별도 서비스**로 떼는 것이
자연스럽고, 코어를 안 건드린다. 이것이 이 저장소에서 **가장 먼저 진짜로 분리될 후보**다.

**개입은 제안까지.** 실행은 사람이 누른다 — 오탐이 정상 플레이어를 벌한다(결정 #48).

**권한**: `observer` + 제안. 개입 실행은 `operator`(사람).

### 4.5 배포봇 (E) — 문을 지킨다

나머지 에이전트가 만든 것을 검토하고, **사람에게 올려 컨펌을 받고, 실행한다.**

**새 검사를 지어내지 않는다.** 이 저장소에는 이미 게이트가 층층이 있다 — 배포봇이 할
일은 그것을 **순서대로 돌리고, 하나라도 걸리면 안 넘어가는 것**이다. 새로 만든 검사는
기존 게이트와 갈리는 순간 어느 쪽이 맞는지 물을 사람이 없어진다.

#### 배포 경로가 둘이고, 서로 어긋날 수 있다

| | **경로 1 · 코드 배포** | **경로 2 · 콘텐츠 발행** |
|:--|:--|:--|
| 무엇이 바뀌나 | 저장소 코드 | 실행 자산 (밸런스·블록·방·적·스킬) |
| 게이트 | `tools/check_all.sh` · 파이썬/프런트 두 스위트 · `npm run build` | `check_draft` (자산별) · 발행 전 전량 재검증 |
| 반영 | 컨테이너 재빌드 | **DB 즉시** + 브라우저는 `/api/content/pack` |
| 되돌리기 | `git revert` + 재배포 | 이전 세대 재발행 |
| 시즌 | 자산이 바뀌면 갈림 | **갈림** |

**둘이 짝이다.** 콘텐츠는 발행(경로 2)만 하면 DB 는 새것인데 **저장소 파일은 옛것**이다 —
브라우저의 오프라인 폴백이 다른 게임을 돌린다. 파일화는 `scripts/publish_content.py`
(ops 서비스)가 따로 하고, 그것을 커밋·배포해야(경로 1) 맞춰진다.

**즉 콘텐츠 한 번 바꾸는 데 배포가 두 번**이고, 그 사이에 드리프트가 산다. 배포봇이
그 짝을 잡는다.

#### 게이트가 안 보는 것 다섯 — 배포봇의 몫

| 묻는 것 | 왜 |
|:--|:--|
| **지금 몇 명이 놀고 있나** | 발행이 진행 중인 판을 반려시킨다 (§3.3). `run_ticket` 에서 `consumed_at IS NULL AND expires_at > now()` 를 센다 |
| **시즌이 갈리나** | `core_version` 이 바뀌면 순위표가 새로 시작한다. 누르는 사람이 그것을 알아야 한다 |
| **골든이 바뀌나** | 밸런스가 바뀌면 저장된 리플레이가 무효가 된다 — CLAUDE.md 가 「기대값을 고치기 전에 그 사실을 먼저 확인한다」고 적어 둔 자리 |
| **DB 와 저장소가 갈라지나** | 발행(2)만 하고 파일화(1)를 안 하면 폴백이 썩는다 |
| **세계 지킴이가 지금 이상을 보고 있나** | **불난 데 배포하지 않는다.** A 의 출력이 E 의 입력이다 |

#### 컨펌에 올리는 것 넷

사람이 누르기 전에 **이 넷이 한 화면에** 있어야 한다.

1. **무엇이 바뀌는가** — 자산별 diff. 값 몇 개가 아니라 어느 축이 움직이는지
2. **누가 만들었는가** — `content_draft.account_id`. 어느 에이전트인지
3. **무엇이 깨지는가** — 열린 티켓 수 · 시즌 분기 여부 · 무효가 되는 리플레이
4. **되돌리는 법** — 그 자리에서 실행할 수 있는 한 줄

**넷째가 없으면 컨펌이 아니라 도박이다.** 되돌리는 법을 모르는 채 누르는 것은 검토가
아니다.

#### 규율 셋

- **읽고 판단만 한다. 누르는 것은 사람이다.** 자동 배포는 이 저장소의 전제(발행이
  시즌을 가른다)와 맞지 않는다.
- **하나라도 걸리면 올리지 않는다.** 「경고지만 넘어감」을 두면 그 상태가 기본이 된다 —
  검증의 두 등급을 섞지 않는 것과 같은 규율(`정비 규칙` 시트 §3).
- **컨펌 뒤 실행까지 한다.** 사람이 누른 다음 손으로 명령을 옮겨 적게 하면, 그 사이에
  다른 것이 섞인다.

**권한**: 검토는 `observer`. 실행은 사람의 `owner` 로 대리한다 — 배포봇 계정에 발행
권한을 주지 않는다 (§3.1).

### 4.6 봇 러너 — 이미 돈다

`scripts/run_bots.py`. 새로 만들 것 없고, 다른 에이전트가 이 파일의 규약을 따른다.

## 5. 무엇으로 만드는가

### 5.1 서버를 따로 안 띄운다

**compose 서비스 하나씩 늘리면 된다.** `bots` 가 정확히 그 템플릿이고, 새 에이전트는
그것을 복사해 `command` 만 바꾼다.

```yaml
  watchdog:
    build: { <<: *build, target: api }   # 개발 의존성 없는 런타임 이미지
    container_name: game-watchdog-1
    restart: unless-stopped
    depends_on: { postgres: {condition: service_healthy},
                  backend:  {condition: service_started} }
    environment:
      GAME_DATABASE_URL: …
      GAME_API_URL: http://backend:8000
    command: ["python", "-m", "scripts.run_watchdog"]
    networks: [game_net]
```

**스케줄러도 안 붙인다.** `run_bots.py` 가 `while True: sleep(TICK_SEC)` 로 돈다 — cron
도 큐도 없다. 주기가 분 단위인 일에 스케줄러를 붙이면 **고장 날 곳이 하나 늘 뿐이다.**

### 5.2 호출은 한 방향이다

```
에이전트 ──HTTP──▶ 게임 백엔드      (game_net 안)
에이전트 ──HTTPS─▶ Anthropic API    (아웃바운드)
게임 백엔드 ──✕──▶ 에이전트          (없다)
```

**백엔드는 에이전트의 존재를 모른다.** 봇 러너가 이미 그렇다 — 백엔드에게는 그냥 계정
하나가 라우트를 부르는 것으로 보인다. 이 방향을 지키면 에이전트를 껐다 켜도 게임이
안 흔들리고, 에이전트가 죽어도 사람은 그대로 논다.

### 5.3 절반은 LLM 이 필요 없다

이것이 이 절의 요점이다. 계획의 절반은 **결정론 스크립트**이고, 그것들이 **먼저**다.

| 에이전트 | LLM | 실제로 무엇인가 |
|:--|:--:|:--|
| **A. 세계 지킴이** | ✕ | SQL 질의 + 임계값 비교. `report_g1.py` 와 같은 결 |
| **B. 판정** | ✕ | `report_g1.py` 가 이미 그것. 주기와 보관만 붙인다 |
| 봇 러너 | ✕ | 이미 돈다 |
| **E. 배포봇** | △ | **게이트 실행은 스크립트.** LLM 은 설명만 (§5.4) |
| **C. 콘텐츠** | ○ | 「이 값이 재미있는가」는 판단이다 |
| **D. CS** | ○ | 문의 분류·의도 파악 |

**LLM 없이 붙는 둘이 순서상 먼저**라는 것이 우연이 아니다. 지켜보고 재는 일은 답이
정해져 있고, 만들고 응대하는 일은 판단이 든다 — **판단이 드는 것을 나중에 붙이는 것이
안전한 순서**이기도 하다.

### 5.4 배포봇에서 LLM 이 하는 일과 안 하는 일

**판정은 게이트가 하고, LLM 은 설명한다.**

| | 누가 |
|:--|:--|
| `check_all.sh` 를 돌리고 통과 여부를 정한다 | **스크립트** (종료 코드) |
| 두 스위트·빌드를 돌린다 | **스크립트** |
| 열린 티켓을 센다 · 시즌이 갈리는지 본다 | **스크립트** (SQL) |
| 무엇이 바뀌었고 왜 위험한지 사람 말로 적는다 | **LLM** |
| 되돌리는 법을 그 자리에 적는다 | LLM (형식은 고정) |
| **넘길지 말지 정한다** | **스크립트** — 하나라도 걸리면 안 넘어간다 |

CLAUDE.md 가 이미 이 규율을 갖고 있다 — 「검사 결과는 종료 코드로 판정한다. 출력 줄을
세는 방식은 도구의 출력 형식이 예상과 다르면 0 을 돌려주고, 그것이 「위반 없음」과
구별되지 않는다」. **LLM 에게 통과 여부를 묻는 것은 출력 줄을 세는 것보다 더 나쁘다.**

### 5.5 라이브러리

| 무엇 | 고른 것 | 왜 |
|:--|:--|:--|
| LLM 호출 | `anthropic` 파이썬 SDK | 얇다. compose 서비스 안에서 함수 호출 하나 |
| 저장소를 읽어야 하는 검토 (E) | Claude Agent SDK / Claude Code | diff·게이트 출력·저장소 맥락이 함께 필요한 자리 |
| 오케스트레이션 | **없음** | §5.6 |
| 스케줄링 | **없음** | `while True: sleep()` (§5.1) |
| 큐 | **없음** | 에이전트끼리 안 부른다 (§5.6) |

키는 `deploy/.env` 에 둔다 — `POSTGRES_PASSWORD` 와 같은 자리이고, **기본값을 두지
않는다.** 없으면 그 서비스가 안 뜬다.

### 5.6 프레임워크를 안 쓰는 이유

에이전트 프레임워크(그래프·큐·상태 기계)가 값하는 것은 **에이전트끼리 서로를 부를 때**다.
여기서는 그런 일이 없다.

- 세계 지킴이는 **사람에게** 올린다. 다른 에이전트를 안 부른다.
- 배포봇은 **게이트를 순서대로** 돌린다 — 그것은 파이썬 함수 다섯 줄이지 그래프가 아니다.
- 콘텐츠 에이전트는 초안을 **DB 에** 놓는다. 배포봇이 그것을 **읽는다.**
  둘은 서로를 모르고 **DB 가 큐 노릇을 한다** (`content_draft` 테이블).

이 저장소는 런타임 의존성에 극도로 보수적이다 — 「`runtime` 이미지에는 uv·ruff·pytest·
git 이 없다. Phase 1 의 런타임 의존성이 0개다」. **프레임워크 하나가 그 성질을 깬다.**
필요해지면 그때 넣는다; 지금 넣으면 안 쓰는 추상이 코드를 덮는다.

## 6. 스케일아웃 전에 하나

`apply_content_reload()` 는 **부른 그 프로세스의 캐시만** 새로 고친다. `LISTEN/NOTIFY`
도 pubsub 도 없다.

**backend 를 2대 이상 띄우는 순간** 발행 후 한동안 replica 마다 `core_version` 이 다르고,
A 가 발급한 티켓을 B 가 반려할 수 있다. 지금 1대라 안 드러날 뿐이다.

Postgres 를 이미 쓰므로 `LISTEN/NOTIFY` 로 충분하다 — 새 의존성이 안 늘어난다.

## 7. 순서

```
1. 세계 지킴이 (A)          ← 지금. 권한 등급 없이도 읽기만이면 붙는다
2. 권한 등급 (3.1)          ← 쓰는 에이전트를 붙이기 전에
3. 아이템 초안 경로 (3.2)   ← 아이템 에이전트 전에
4. 발행과 열린 티켓 (3.3)   ← 콘텐츠 에이전트가 잦아지기 전에
5. 배포봇 (E)               ← C 보다 먼저. 문이 없으면 검토 없이 세계가 바뀐다
6. 콘텐츠 에이전트 (C)
7. 발행 전파 (§5)           ← backend 2대 전에
8. CS 분리 (D)              ← 사용자가 늘면
```

**5 가 6 보다 먼저인 이유**는 순서가 뒤집히면 검토 없는 창이 생기기 때문이다. 만드는
에이전트를 먼저 붙이면 그동안 사람이 손으로 검토하게 되는데, 그 손이 바로 오늘
아홉 건을 놓친 손이다.

**1 이 먼저인 이유**는 나머지를 안전하게 만들기 때문이다. 지켜보는 것이 있으면 2~7 에서
무언가 틀어졌을 때 **그날 안에** 드러난다 — 오늘 찾은 결함들은 이틀에서 며칠씩 조용히
돌고 있었다.

## 8. 안 하기로 한 것

- **MSA 전환.** 코어를 분해하면 `core_version` 정합성을 손으로 관리하게 된다 (§2).
- **에이전트에게 발행 권한.** 시즌이 아무도 모르게 갈린다.
- **에이전트가 이상을 자동으로 고치기.** 원인이 사라지고 증상만 남는다 (§4.1).
- **자동 밴.** 불일치의 원인은 셋이고 그중 하나는 우리 버그다 (결정 #47·#48).
- **자동 배포.** 배포봇도 안 누른다 — 발행이 시즌을 가르고, 시즌은 되돌려도 흔적이 남는다.
- **배포봇이 새 검사를 만들기.** 기존 게이트와 갈리는 순간 어느 쪽이 맞는지 물을 사람이
  없어진다. 있는 것을 순서대로 돌리는 것이 그 몫이다.
- **LLM 에게 통과 여부를 묻기.** 판정은 종료 코드가 한다 (§5.4).
- **에이전트 프레임워크·큐·스케줄러.** 에이전트끼리 안 부르고, DB 가 이미 큐 노릇을
  한다 (§5.6). 런타임 의존성 0개라는 성질을 깨지 않는다.
- **에이전트 전용 서버.** compose 서비스 하나면 된다 (§5.1).
