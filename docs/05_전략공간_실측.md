# 전략 공간 실측 — R2 조기 감지

> **리스크 R2:** 단일 정답 규칙표로 수렴 (TDD §12, 영향 치명)
> **GDD §11 지표:** 최상위 클리어 규칙표가 2가지 이상의 서로 다른 전략으로 갈리는가

측정: 3방 연쇄(`open_field → corridor → pillars`) × 200런, 적은 각자의 규칙표로 싸운다.
재현: `uv run python -m scripts.run_batch --runs 200`

## 판정 — R2 는 현재 발생하지 않았다

**클리어 가능한 전략이 3가지이고 서로 다르다.** 카이팅(거리 유지), 문 지키기(지형 이용),
회복타일(자원 운용)은 같은 발상의 변형이 아니다. GDD §11 의 "2가지 이상" 조건은 충족한다.

다만 승률이 100 / 87 / 47 로 갈려 있어 최적해는 하나다. Phase 4 W18 의 밸런싱에서
이 격차를 좁히는 것이 R2 대응의 본론이다.

## 가장 중요한 발견 — 순서와 플래그가 결과를 가른다

`sniper` 와 `g0_kite` 는 **거의 같은 블록**을 쓴다. 둘 다 후퇴하고 둘 다 사격한다.
차이는 플래그로 둘을 교대시키느냐뿐이다.

| | 규칙 발동 분포 | 결과 |
|:--|:--|:--|
| `sniper` | 후퇴 36회 · 사격 2회 | LOSS 43틱 HP 0 |
| `g0_kite` | 후퇴 4 · 사격 4 · 사격 4 | **WIN 15틱 HP 100** |

`sniper` 는 후퇴(`적거리 <= 2`)를 사격보다 위에 뒀다. 근접 적이 계속 붙으므로 후퇴가
매 틱 참이 되고, 사격 규칙까지 평가가 내려가지 않는다. 결국 벽에 몰려 14틱을
"목표 없음"으로 버리고 죽는다.

`g0_kite` 는 후퇴할 때 `FLAG_A` 를 세우고, 다음 틱에 그 플래그를 조건으로 사격한 뒤
플래그를 내린다. 같은 블록이 교대로 돌아간다.

> **이것이 GDD §3.5 가 플래그를 넣은 이유의 실증이다.** 틱 간 상태가 없으면 카이팅은
> 표현할 수 없다. 그리고 이것이 P1(실패는 정보다)이 작동하는 모습이기도 하다 —
> 규칙별 발동 횟수만 보면 "후퇴 36 / 사격 2" 에서 고칠 곳이 즉시 특정된다.

## 부수 발견

**셀렉터 하나만 노리는 규칙표는 그 적이 없는 방에서 아무것도 못 한다.**
`focus_summoner` · `focus_ranged` 가 첫 방(돌진형만 나옴)에서 0방 클리어다. 셀렉터가
대상을 못 고르면 규칙이 건너뛰어지고, 남는 것은 DEFAULT(가장 가까운 적에게 접근)뿐인데
그것은 공격을 하지 않는다.

TDD §5.2 의 DEFAULT 가 "접근"만인 결과다. 의도된 설계이지만, 플레이어가 이 함정에
빠졌을 때 로그에 `모든 규칙 거짓 → DEFAULT` 가 매 틱 찍히므로 원인은 드러난다.
