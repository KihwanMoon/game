# 결정 대기 목록

> 문서 다섯 곳에 흩어져 있던 미결 사항을 한 곳에 모았다. **정하는 순서가 비용을 정한다.**
> 정해지면 이 표에서 지우고 원래 문서에 결과를 적는다.

## 읽는 법

분류는 중요도가 아니라 **언제 정해야 싼가**다.

| 분류 | 뜻 |
|:--|:--|
| 🔴 **동결** | 늦게 정할수록 비싸진다. 지나면 되돌리는 데 데이터 폐기가 따른다 |
| 🟠 **차단** | 지금 당장 비싸지진 않지만 특정 작업이 이것 없이는 시작되지 않는다 |
| 🟡 **조정** | 언제든 정할 수 있다. 밸런스·튜닝 |
| ⚪ **외부** | 우리가 정하는 것이 아니다. 확인하거나 기다린다 |

## 🔴 동결 — 늦으면 되돌릴 수 없다

| # | 결정 | 출처 | 선택지 | 동결 시점 · 늦으면 |
|:-:|:--|:--|:--|:--|
| 01 | **시드를 누가 발급하는가** | `07` §10-2 | 클라이언트(현재) / 서버 | **랭킹 공개 전.** 지금은 한 줄. 랭킹이 생긴 뒤엔 그때까지의 기록이 **전부 무효** |
| 02 | **아이템 접사를 시드에서 파생시킬 것인가** | `07` §4 · `09` §8 | 시드 파생 / 서버 발급 / 클라이언트 굴림 | **첫 아이템이 나가기 전.** 뒤에 바꾸면 그때까지 나온 아이템이 전부 무효. 거래가 얹혀 있으면 되돌릴 수 없다 |
| 03 | **L1→L2 마이그레이션 방식** | `07` §9 | (a) 전부 폐기 (b) 재현 가능한 것만 승계 (c) 전부 승계 | **아이템을 localStorage 에 넣기 전.** (b) 를 쓰려면 그 시점부터 획득 경로를 함께 저장해야 한다. 나중에 붙일 수 없다 |
| 04 | **규칙이 스킬을 가리키는 방식** | `10` §3 · S1 | (a) 슬롯 번호 (b) 스킬 정체 ← 권장 | **스킬 구현 전.** 이벤트 로그 `fired` 필드와 디자인 규약(4번째 상태)이 함께 바뀐다. 뒤에 바꾸면 저장된 규칙표를 마이그레이션해야 한다 |
| 05 | **골든에 전리품 축을 넣을 것인가** | `07` §4 | 넣는다 / 전투 로그만 | **아이템이 코어에 들어가는 시점.** 안 넣으면 파생식을 바꿔도 게이트가 침묵한다 |
| 06 | **랭킹 시즌 = 코어 버전인가** | `07` §7 | 코어 버전별 분리 / 통합 | **첫 밸런스 패치 전.** 통합해 두면 재현되지 않는 기록이 표에 남는다 |
| 07 | **아이템 귀속 규칙** | `09` §14 I6 | 획득 즉시 / 거래 후 / 없음 | **거래 개시 전.** 뒤에 조이면 이미 유통된 물량이 예외가 된다 |
