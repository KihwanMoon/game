| # | 결정 | 결과 |
|:-:|:--|:--|
| — | 스탯 성장 총량 | **상한 없음.** GDD §0 을 2단 구조로 개정했다 — P1 의 유효 구간이 초·중반으로 한정된다 |
| 13·14 | 장비·소모품 DSL 노출 | **장비 전용 블록을 만들지 않는다.** 장비는 전투 전에 캐릭터 능력치·스킬로 녹고, 규칙표는 캐릭터만 읽는다. 사거리는 이미 스탯 참조로 읽히므로 활로 바꾸면 같은 규칙표가 저절로 다르게 돈다 |
| 51 | 힘·민첩·지능 변환표 | **축마다 여는 것이 다르다.** 힘=공격+체력, 민첩=선공권+방어, 지능=CPU+스킬위력. 셋이 공격력으로 수렴하면 배분이 선택이 아니라 계산이 된다. **「회피」는 넣지 않았다** — 이 게임의 회피는 스탯이 아니라 예고 타일에서 비켜서는 것이고, 굴림을 더하면 P1 이 무너진다. **지능이 여는 CPU 에만 상한(+8)이 있다** — CPU 는 표현력이고 표현력이 무한하면 정교한 로직의 가치가 사라진다 |
| 07 | 아이템 귀속 | **거래 후 귀속.** 주운 것은 한 번 팔 수 있고, 산 사람에게 묶인다. 자유 거래면 같은 아이템을 A→B→A 로 돌려 계정 사이에 화폐를 씻을 수 있고 봇 파밍이 최적 전략이 된다. 완전 귀속이면 경매장이 죽고 **유일한 화폐 배출구**가 사라진다. 기존 아이템은 전부 미귀속으로 시작한다 — 유통량이 거의 0 이라 실질 차이가 없고 예외 규칙을 만들지 않는 편이 낫다 |
| 54 | 소모품 다종화의 DSL 노출 | **`USE_ITEM[kind]` (블록 v6).** 파라미터가 카탈로그 id 가 아니라 **태그**라, 물약을 여러 등급으로 늘려도 블록 목록이 안 바뀌고 랭킹 시즌이 갈리지 않는다. `USE_POTION` 은 별칭으로 남는다 — 지우면 저장된 규칙표와 골든이 깨진다. 시즌 비용은 지금이 사실상 0 이라 여기서 치렀다 |
| 42 | 아이템 등급 체계 | **3등급 · 괘선 굵기로.** 보통 1px · 상급 2px · 유물 2px+모서리. 의미색 셋이 이미 배정돼 등급색을 쓸 수 없고, 넷을 넘으면 이 표기가 부족해진다. 셀 크기는 등급과 무관하게 같다 — 달라지면 격자가 흔들린다 |
| 02 | 아이템 접사 파생 | **서버 발급.** `items/loot.py` 가 `secrets` 로 굴린다 — 게임 난수가 아니라 예측 불가능해야 하는 값이고 코어 밖이다. 클라이언트는 아이템을 만들 수 없다 |
| 05 | 골든에 전리품 축 | **필요 없어졌다.** 전리품이 시뮬레이션 산출물이 아니게 되면서(#02) 이 질문 자체가 소멸했다 (`설계/4_아이템` §11) |
| 06 | 랭킹 시즌 = 코어 버전 | **분리한다.** `core_version` 이 시즌 이름이다. 밸런스나 블록 목록이 바뀌면 과거 기록이 재현되지 않으므로 표가 새로 시작한다 |
| 34 | 사망 시 아이템 상실 범위 | **장비 하나.** 장착 중이면 파손, 가방이면 삭제. 파손된 장비는 복구 전까지 그 자리가 비어 있는 것과 같다 (`store/equipment.py`) |
| — | **소셜 로그인** (2026-09-05) | **구글 하나만, G1 판정 뒤에.** 승격 구조가 이미 그 모양이라 새 구조가 아니다 — `login_id`/`password_hash` 옆에 `oauth_provider`·`oauth_subject` 를 두면 계정 id 가 그대로라 세이브·티켓·제출·아이템이 전부 따라온다. **지금 하지 않는 이유**는 로드맵 원칙 1(재미 검증 전에 자산을 만들지 않는다)이다. **미루는 값**도 적어 둔다: 오늘은 기기를 잃으면 계정과 장비가 함께 사라지고(CLAUDE.md 가 「아이템과 거래가 붙기 전에 승격 경로가 필요하다」고 적어 둔 그 자리다 — 아이템과 경매는 이미 붙었다), G1 은 하필 「재도전」을 재므로 테스터가 계정을 잃으면 그 표본이 버려진다. 구글만 고른 이유는 표준 OIDC 라 검증 경로가 한 번만 필요하고, 카카오·네이버를 나중에 붙일 때 그 코드가 재사용되기 때문이다 |
| 17 | 튜토리얼 설계 | **규칙 3개짜리 단계 다섯.** ① 규칙 한 줄 ② 순서가 결과를 바꾼다 ③ 플래그로 교대시킨다 ④ CPU 예산 ⑤ 실패를 읽는다. 각 단계는 **시작 규칙표로는 지고 해답으로는 이긴다** — 그 대비가 가르치는 내용 자체이며 `tests/test_tutorial.py` 가 매 커밋 확인한다. 단계를 열면 **틀린 규칙표가 먼저 실린다**: 실패한 판을 한 번 보고 나서 고치는 것이 이 게임의 학습 방식이다 (P1) |
