## 1. 한 줄

> **캐릭터를 조종하지 않는다. 캐릭터의 판단 규칙을 설계하고, 그 규칙이 살아남는지 본다.**

장르는 코딩형 로그라이크 그리드 오토배틀. 1회 런 15~25분.

## 2. 세 기둥 — 모든 결정이 여기 걸린다

| 기둥 | 내용 | 검증 질문 |
|:--|:--|:--|
| **P1. 실패는 정보다** | 모든 패배는 "어떤 규칙이 왜 잘못 발동했는지" 로 환원된다 | 죽고 나서 **고칠 곳이 특정되는가?** |
| **P2. 그리드는 이유가 있어야 한다** | 거리 스칼라로 대체 가능한 메커니즘은 넣지 않는다 | 이 기믹이 **1차원에서도 성립하는가?** |
| **P3. 제약이 재미다** | 무제한 규칙 슬롯은 사고를 죽인다 | **트레이드오프가 발생하는가?** |

그리고 이 셋을 떠받치는 기술 불변 조건:

> **R5. 같은 시드는 같은 결과를 낸다.**
> 깨지면 리플레이·데일리 챌린지·헤드리스 밸런싱·서버 검증이 **한꺼번에** 무너진다.

## 3. 코어 루프 — 3계층에서 4계층으로

GDD v2 는 3계층이었다. **지속 몬스터(`설계/6_몬스터` §5)가 네 번째를 만든다.**

```
┌─ World Loop ─────────────────────────────── 신규 ─┐
│  런과 런 사이에 세계가 변한다                       │
│  · 지속 몬스터가 성장한다 (플레이어·몬스터 사냥)     │
│  · 내 아이템이 몬스터에게 넘어가 있다                │
│  · 랭킹·거래가 갱신된다                            │
│  ┌─ Run Loop ─────────────────────────────────┐  │
│  │  런 시작(프리셋·티켓) → 층 공략 → 사망/클리어  │  │
│  │  → 결산 → 영구 해금 → 재도전                 │  │
│  │  ┌─ Room Loop ──────────────────────────┐  │  │
│  │  │  입장 → 전투(자동) → 클리어 → 보상 선택 │  │  │
│  │  │  → [규칙 편집] → 다음 방              │  │  │
│  │  │  ┌─ Tick Loop ────────────────────┐  │  │  │
│  │  │  │  7페이즈. 플레이어 입력 없음      │  │  │  │
│  │  │  └────────────────────────────────┘  │  │  │
│  │  └──────────────────────────────────────┘  │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

**World Loop 이 이 게임의 성격을 바꾼다.** 지금까지는 매 런이 백지에서 시작했다.
이제 "지난번에 나를 죽인 그 개체가 내 장비를 들고 저 아래 있다" 가 성립한다.

각 계층에서 플레이어가 하는 일:

| 계층 | 플레이어 | 편집 가능 |
|:--|:--|:-:|
| Tick | **관전만** | ✕ |
| Room | 보상 선택 · **규칙 편집** | ○ |
| Run | 프리셋 선택 · 장비/스킬 구성 | ○ |
| World | 표적 선정 · 거래 · 랭킹 | ○ |

**전투 중 개입은 없다.** 사전 설계의 가치가 이 규칙 하나에 걸려 있다.

## 4. 성장 — 네 축 전부가 "표현력" 이다

GDD §0 이 못박은 것: *성장은 로직 설계 실력으로 이루어진다.*
이 원칙 아래에서 레벨·아이템·스킬을 전부 **같은 방향**으로 정렬한다.

| 축 | 올리는 것 | 효과 |
|:--|:--|:--|
| **규칙 슬롯** | 층 기록 · 확장 슬롯 모듈 | 규칙을 더 쓸 수 있다 |
| **CPU 예산** | 연산 코어 모듈 | 조건을 더 정교하게 쓸 수 있다 |
| **블록 해금** | 메타 진행 · 센서/액추에이터 모듈 | 새 인지·행동을 쓸 수 있다 |
| **플래그** | 서브루틴 모듈 | 상태를 기억할 수 있다 |

여기에 **스탯**(HP·공격력·방어력)이 있지만 **의도적으로 낮게 유지한다** (전 구간 20~30%).
스탯으로 뭉갤 수 있으면 규칙표를 고칠 이유가 사라지고 P1 이 죽는다.

### 레벨을 어떻게 볼 것인가 ★ 미결 (`결정/1_결정대기목록` #10)

> **레벨은 위 네 축을 묶어 보여주는 이름이고, 아이템·스킬의 요구조건 게이트다.**
> 전투 스탯을 직접 올리지 않는다.

이것이 기본안이다. 전투 스탯을 올리는 레벨을 원한다면 **GDD §0 을 함께 고쳐야 한다** —
게임의 정체성을 바꾸는 결정이다.

### 적의 성장도 같은 축이다 (`설계/6_몬스터` §2)

몬스터가 크면 **스탯이 아니라 규칙표가 정교해진다.** 레벨 3 궁수는 "보이면 쏜다",
레벨 20 은 "엄폐를 유지하며 사거리를 재고 회복 타일을 끊는다".

도감이 그 규칙표를 공개하므로 플레이어는 **무엇이 달라졌는지 읽을 수 있다.**
진 이유가 "공격력이 높아서" 가 아니라 "저쪽 규칙 4번이 내 규칙 2번을 받아친다" 가 된다 — P1.

## 5. 세 시스템이 맞물리는 자리

새로 설계한 아이템·스킬·몬스터는 **따로 노는 세 시스템이 아니다.** 셋 다 같은 규격을
공유하고, 서로를 통해 순환한다.

```
        요구조건 {stat, min}  ← 아이템·스킬이 같은 규격 (09 §6, 10 §1)
                 │
   ┌─────────────┼─────────────┐
   │             │             │
 아이템 ─── 액추에이터 모듈 ──→ 스킬       (10 §5 — 스킬 획득은 아이템을 탄다)
   │                            │
   │ 유저 사망 시 이전            │ 규칙표가 지시
   ↓                            ↓
 몬스터 ←──── 사냥 ──────────── 전투
   │                            │
   └── 도감이 규칙표·장비 공개 ──┘        (12 §8 — 위키가 아니라 표적 목록)
              │
              ↓
        되찾으러 간다               ← World Loop 의 동기
```

**대칭이 핵심이다.** 플레이어와 몬스터는 같은 레코드다 (`설계/6_몬스터` §7) — 레벨·스탯·규칙표·
스킬·장비가 같은 필드다. 코드가 둘을 가르지 않는다. 이미 그렇게 만들어져 있다
(적도 규칙표로 행동하고 `policies` 로 개체마다 다른 정책을 돈다).

## 6. 시스템 요약

세부는 각 정본 문서에 있다. 여기서는 **무엇이 있는지**만.

### 아이템 (`설계/4_아이템`)
3종 — 장비 / 소모품 / 퀘스트. 장비는 6슬롯(무기 2 · 투구 · 갑옷 · 신발 · 장갑),
무기는 한손/양손/보조(방패). 인벤토리 칸 제한. 레벨·스탯 요구조건.
**요구조건은 장비 보너스를 제외한 소재 능력치로만 판정한다** — 안 그러면 착용 순서가
결과를 바꿔 R5 가 깨진다.

### 스킬 (`설계/5_스킬`)
계열 5종 — ATTACK / MOVE / GUARD / STATUS / UTILITY. 형태는 SINGLE·LINE·AREA·CONE·SELF
(P2 — 1차원에서 성립하지 않아야 한다). 규칙표는 **자리 번호가 아니라 스킬 정체**를
가리킨다. 획득은 아이템 액추에이터 모듈과 메타 해금을 탄다.

### 몬스터 (`설계/6_몬스터`)
등급 3종(일반·엘리트·보스) × 지속성 2종. 지속 몬스터는 여러 플레이어가 같은 개체를
만나고 성장하며 플레이어의 아이템을 가져간다. **결정론은 스냅샷 봉인으로 지킨다.**

### 저장·멀티플레이 (`설계/3_저장과_멀티플레이`)
3계층 — L1 기기 로컬 / L2 계정 소유 / L3 공용 원장. 서버는 결과를 받지 않고
**재시뮬해서 확정**한다. 아이템은 스탯이 아니라 획득 경로를 저장한다.
