# 코딩형 던전 RPG 그리드 RPG — 개발 로드맵

> **전제:** 1인 개발 / 주 15~20시간 투입 기준. 팀 2~3인 병렬 시 §6의 압축안 참조.
> **기준일:** 2026-08-27 시작 가정

---

## 0. 일정 설계 원칙

1. **재미 검증이 끝나기 전에는 자산을 만들지 않는다.** 그래픽·사운드·절차생성·파밍은 전부 Phase 2 이후.
2. **각 Phase 끝에 게이트(Gate)를 둔다.** 게이트 조건 미충족 시 다음 Phase로 넘어가지 않고 **되돌아가거나 중단**한다.
3. **Phase 1 프로토타입은 버릴 코드다.** 예쁘게 짜지 말고 빠르게 검증한다.

## 3. Phase 1 — 수직 슬라이스 (3주) ★ 최중요

> **이 Phase의 유일한 목적:** "실패 → 규칙 수정 → 재도전"이 재미있는지 확인.
> **그래픽 없음. 절차생성 없음. 파밍 없음. 층 없음. 메타 프로그레션 없음.**

### 주차별 계획

| 주 | 작업 |
|:-:|:--|
| W1 | 틱 엔진 7페이즈, 그리드/타일, BFS 이동, 기본 전투 판정 |
| W2 | RuleVM (조건 평가, 셀렉터, 플래그, CPU 예산), 규칙표 JSON 로딩 |
| W3 | 고정 맵 3개, 적 3종(돌진/사격/소환), 텍스트 로그 출력, 헤드리스 배치 러너 |

### 범위
- 맵: 손으로 만든 고정 방 3개 연속
- 규칙 입력: **JSON 파일 직접 편집** (UI 없음)
- 출력: 터미널 텍스트 로그 (틱별 조건값 + 발동 규칙)

### 게이트 G1 (통과 못 하면 설계 재검토)
- [ ] 테스터 5명 중 3명 이상이 첫 패배 후 **자발적으로 JSON을 고쳐 재도전**했는가
- [ ] 같은 방을 클리어하는 규칙표가 **서로 다른 2가지 이상** 나왔는가
- [ ] 평균 재도전 횟수 3회 이상인가

> G1 실패 시: DSL 표현력 부족 또는 적 설계 문제. Phase 2로 넘어가지 말고 W2~W3를 반복한다.

## 4. Phase 2 — 코어 완성 (5주)

| 주 | 작업 | 산출물 |
|:-:|:--|:--|
| W4 | Room Loop — 노드 그래프, 보상 선택, 방 사이 규칙 편집 | 방 연쇄 진행 |
| W5 | Run Loop — 사망/결산, 영구 해금, 몬스터 도감, 프리셋 8슬롯 | 메타 프로그레션 |
| W6 | 그리드 전술 — LOS, 텔레그래프, 포위 페널티, 확장 타일 6종 | 전술 성립 |
| W7 | 어뷰징 차단 — 추격자 스폰, 회복 감쇠, 층 스케일 / 적 5종 추가 | 밸런스 1차 |
| W8 | 디버깅 UX 1차 — 로그 패널, 배속, 사망 리플레이 15틱 | 관전 가능 |

**게이트 G2**
- [ ] 무한 카이팅·회복 어뷰징으로 클리어 가능한 구멍이 없는가 (헤드리스 1,000런 검증)
- [ ] 사망 후 "어느 규칙이 왜 틀렸는지" 를 로그만 보고 특정할 수 있는가
- [ ] 도감으로 적 규칙을 본 뒤 승률이 유의미하게 상승하는가

## 5. Phase 3 — 프로덕션 이관 (5주)

| 주 | 작업 |
|:-:|:--|
| W9~W10 | 시뮬레이션 코어 TypeScript 재작성 + 골든 리플레이로 Python 결과와 대조 검증 |
| W11~W12 | **규칙 에디터 UI** — 블록 드래그, 우선순위 정렬, CPU 게이지, 텍스트 뷰 토글 |
| W13 | Canvas 전투 렌더러, 로그 패널 통합, 되감기 슬라이더 |

**게이트 G3**
- [ ] TS 코어와 Python 코어가 동일 시드에서 **완전 동일한 결과**를 내는가
- [ ] 규칙 에디터로 규칙표 하나 짜는 데 3분 이내인가 (JSON 편집보다 빨라야 함)

> ⚠ W11~W12가 전 일정 중 **가장 큰 리스크**. 에디터 UX가 번거로우면 게임 자체가 죽는다. 이 구간에만 별도로 사용성 테스트 2회 배정.

## 8. 팀 병렬 시 압축안 (2~3인)

| 역할 | 담당 | 압축 효과 |
|:--|:--|:--|
| 개발 A | 시뮬 코어, RuleVM, 생성기 | — |
| 개발 B | 에디터 UI, 렌더러, 로그 패널 | Phase 3을 5주 → 3주 |
| 기획/밸런싱 | 룸 템플릿, 적 규칙표, 헤드리스 밸런싱 | Phase 4를 6주 → 4주 |

- 병렬 시 **총 24주 → 약 16주**
- 단, **Phase 1은 병렬화하지 말 것.** 인원을 늘리면 오히려 "검증 전 자산 생산"이 시작되어 원칙 1이 깨진다.

## 10. 주간 운영 방식

- 매주 금요일: 헤드리스 배치 실행 결과 리뷰 (승률·평균 틱·규칙 발동 분포)
- 게이트 판정은 **혼자 하지 않는다.** 최소 3인 이상의 외부 플레이 데이터로 판정.
- 스코프 추가 요청은 전부 §GDD 10장 "추가 기능 후보"로 보내고, 현재 Phase에서는 반영하지 않는다.
