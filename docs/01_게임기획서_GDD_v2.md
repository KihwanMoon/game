# 코딩형 로그라이크 그리드 RPG — 게임 기획서 (GDD v2)

> v1(초안) 대비 변경점: 코어 방향성 확정, 메타 프로그레션 신설, DSL 표현력 확장, 그리드 전술성 확보, 아이템 2축 분리, 어뷰징 차단 규칙, 디버깅 UX 신설

---

## 0. 방향성 결정 (Design Pillar)

v1의 가장 큰 문제는 **"퍼즐형(로직으로 성장)"과 "파밍형(스탯으로 성장)"이 한 문서에 공존**한다는 점이었다. 두 축은 밸런싱 방향이 정반대이므로 하나를 주축으로 확정한다.

- **주축(Primary): 퍼즐형** — 플레이어의 성장은 *로직 설계 실력*으로 이루어진다.
- **보조축(Secondary): 파밍** — 아이템은 스탯을 올리는 것이 아니라 **로직 표현력을 확장**하는 수단으로 재정의한다.
- **결과:** "좋은 장비를 먹어서 이겼다"가 아니라 **"좋은 장비 덕분에 더 정교한 로직을 짤 수 있어서 이겼다"** 가 되도록 설계한다.

### 세 가지 설계 원칙

| 원칙 | 내용 | 검증 질문 |
|:--|:--|:--|
| P1. 실패는 정보다 | 모든 패배는 "어떤 규칙이 왜 잘못 발동했는지" 로 환원되어야 함 | 죽고 나서 고칠 곳이 특정되는가? |
| P2. 그리드는 이유가 있어야 한다 | 거리 스칼라만으로 대체 가능한 메커니즘은 넣지 않음 | 이 기믹이 1차원에서도 성립하는가? |
| P3. 제약이 재미다 | 무제한 규칙 슬롯은 사고를 죽인다 | 트레이드오프가 발생하는가? |

## 1. 게임 개요

- **장르:** 코딩형 로그라이크 그리드 오토배틀
- **핵심 컨셉:** 플레이어는 캐릭터를 직접 조종하지 않는다. 캐릭터의 **판단 규칙(AI)** 을 설계하고, 그 규칙이 던전에서 살아남는지를 관전·검증·수정한다.
- **플랫폼:** PC (웹 빌드 우선, 이후 Steam)
- **1회 런 목표 시간:** 15~25분
- **타깃:** 자동화·최적화 게임 선호층 (Gladiabots, Zachtronics, Screeps, Slay the Spire 교집합)

## 2. 코어 루프 (3계층)

v1에는 틱 루프만 있고 상위 루프가 없었다. 로그라이크는 **상위 루프에서 재미가 발생**한다.

### 2.1 Tick Loop (전투 내부, 자동)
```
틱 시작 → 상태 갱신 → 인지 스캔 → 규칙 평가 → 행동 실행 → 판정 → 틱 종료
```
- 플레이어 입력 없음. 관전 및 로그 확인만 가능.
- 속도 제어: 일시정지 / 1x / 2x / 4x / 즉시 실행

### 2.2 Room Loop (방 단위)
```
방 입장 → 전투(자동) → 클리어 → 보상 선택 → [규칙 편집 가능] → 다음 방
```
- **규칙 편집은 방 사이에서만 가능** (전투 중 개입 불가 = 사전 설계의 가치 보존)
- 보상: 모듈 / 스탯 접사 장비 / 포션 / 규칙 슬롯

### 2.3 Run Loop (런 단위) — **신규**
```
런 시작(프리셋 로드) → 층 공략 → 사망 or 클리어 → 결산 → 영구 해금 → 재도전
```

**사망 시 소멸:** 장비, 임시 모듈, 층 진행도, 포션
**사망 시 영구 보존:**

| 항목 | 설명 |
|:--|:--|
| 블록 해금 | 런 중 처음 접한 인지 변수·행동 블록은 영구 해금 |
| 규칙 슬롯 상한 | 층 도달 기록에 따라 시작 슬롯 +1 (최대 +4) |
| 몬스터 도감 | 처치·조우한 적의 **AI 규칙이 그대로 공개됨** (핵심 학습 재료) |
| 코드 라이브러리 | 성공한 규칙 세트를 프리셋으로 저장 (최대 8슬롯), 다음 런 시작 시 로드 |

> **설계 의도:** 도감으로 적의 로직이 공개되므로, 실패한 런조차 "적을 카운터하는 규칙"이라는 자산을 남긴다. → P1 충족

## 3. DSL 심화 설계 (v1 최대 보완 지점)

v1은 인지 변수 6개 × 행동 6개로, 3~4판이면 단일 정답 규칙표로 수렴한다. 아래 4가지 축을 추가해 조합 공간을 확장한다.

### 3.1 규칙 구조 (확장)

```
[우선순위 N] IF <조건식> THEN <행동> [TARGET <셀렉터>] [SET <플래그>]
```

- 조건식: `AND` / `OR` / `NOT`, 최대 3항까지
- 위에서부터 평가하여 **최초로 참이 되는 규칙 1개만** 실행 (결정론 보장)

### 3.2 인지 변수 (Perception) — 4개 카테고리

**자기 상태**
- `내 HP%`, `내 포션 수`, `내 위치가 회복타일인가`, `내 쿨타임[스킬] 완료`, `내 상태이상(중독/둔화/기절)`

**적 정보**
- `가장 가까운 적 거리`, `시야 내 적 수`, `적 유형 존재(근접/원거리/소환사/자폭)`, `대상 HP%`, `대상이 시전 중인가(텔레그래프)`

**지형/공간** ← *그리드 정당화의 핵심*
- `내 위치가 시야에 노출됨(LOS)`, `엄폐 가능 벽까지 거리`, `내 주변 8칸 중 이동 가능 칸 수(포위도)`, `위험 예고 타일 위에 있는가`, `가장 가까운 문/계단 거리`

**시간/자원**
- `현재 방 체류 틱`, `내 CPU 여유`, `플래그[A~D] 상태`

### 3.3 타겟 셀렉터 (Target Selector) — **신규**

v1은 "가장 가까운 적"만 가능했다. 이것이 표현력 부족의 최대 원인.

- `NEAREST` / `LOWEST_HP` / `HIGHEST_THREAT` / `TYPE(원거리)` / `TYPE(소환사)` / `CASTING` / `BOSS`

> 예: `IF 시야 내 적 수 >= 2 THEN 공격 TARGET TYPE(소환사)` — 소환사 우선 처리라는 전술이 성립

### 3.4 행동 (Action) — 확장

| 분류 | 행동 |
|:--|:--|
| 공격 | 기본 공격, 스킬 1/2, 범위 공격 |
| 이동 | 대상에게 접근, 후퇴(거리 벌리기), **엄폐물 뒤로 이동(LOS 차단)**, 문/계단으로 이동, 회복타일로 이동 |
| 제어 | 대기(HOLD), 포션 사용, 플래그 설정 |

### 3.5 상태 플래그 (Memory) — **신규**

- `FLAG_A ~ FLAG_D` 4개의 불리언 메모리 제공
- 틱 간 상태 유지가 가능해지므로 **카이팅·유인·연계**가 구현 가능해진다

> 예 (카이팅 구현):
> ```
> [1] IF 적 거리 <= 1                  THEN 후퇴          SET FLAG_A = true
> [2] IF FLAG_A AND 쿨타임[사격] 완료   THEN 공격 TARGET NEAREST  SET FLAG_A = false
> ```

### 3.6 제약 시스템 (CPU 예산) — **신규**

- 각 규칙은 조건 항 수에 비례한 **CPU 비용**을 가짐 (1항=1, 2항=2, 3항=4)
- 캐릭터의 틱당 CPU 예산 내에서만 규칙표를 구성 가능 (초기 예산 8)
- **효과:** "정교한 조건 1개 vs 단순한 조건 3개" 라는 트레이드오프 발생 → P3 충족
- 예산은 모듈 아이템으로 증가

## 4. 그리드 전술 시스템 (P2 이행)

v1 설계는 2D 배열이 필요 없었다. 아래 요소로 공간을 의미 있게 만든다.

### 4.1 시야(LOS) 시스템
- 원거리 적은 **직선 시야가 확보될 때만** 공격 가능
- 벽 뒤 엄폐가 유효 전술이 되며, `엄폐물 뒤로 이동` 행동이 의미를 가짐

### 4.2 텔레그래프(예고) 공격
- 보스·정예는 N틱 전에 **피격 예정 타일을 붉게 표시**
- `위험 예고 타일 위에 있는가` 조건으로 회피 로직 설계 가능
- **관전의 긴장감을 만드는 핵심 장치** (오토배틀의 지루함 해소)

### 4.3 포위 및 통로
- 근접 적은 인접 8칸을 점유하며, 포위 시 피해 증가
- 좁은 통로로 유인해 1:1 구도를 만드는 전략이 유효

### 4.4 타일 확장

| ID | 타일 | 판정 | 메커니즘 |
|:-:|:--|:--|:--|
| 0 | 바닥 | 이동 가능 | 기본 |
| 1 | 벽 | 불가 | 이동·LOS 차단 |
| 2 | 파괴 가능 벽 | 불가→가능 | 공격으로 파괴, 통로 개설 |
| 3 | 가시덤불 | 가능(둔화) | 이동 2틱 소모, LOS 미차단 |
| 4 | 문 | 조건부 | 클리어 시 개방 |
| 5 | 생명의 샘 | 가능 | 틱당 회복, **잔여량 소진 시 소멸** |
| 6 | 계단 | 가능 | 보스 처치 시 생성 |
| 7 | 용암 | 가능 | 체류 시 틱당 피해 |
| 8 | 함정 | 가능 | 최초 진입 시 발동, 이후 노출 |
| 9 | 엄폐물 | 불가 | LOS 차단, 파괴 불가 |

## 5. 몬스터 AI 설계

> **핵심 설계:** 몬스터도 **플레이어와 완전히 동일한 DSL로 기술**한다. 도감에서 그 규칙표를 그대로 보여준다.
> → 몬스터 제작 비용 절감 + 플레이어 학습 자료 + 밸런싱 도구 일원화

| 유형 | 행동 특성 | 플레이어에게 요구하는 대응 |
|:--|:--|:--|
| 돌진형 | 최단거리 접근, 인접 시 연타 | 포위 회피, 통로 유인 |
| 사격형 | LOS 확보 시에만 공격, 접근 시 후퇴 | 엄폐 이동 또는 급속 접근 |
| 소환형 | 3틱마다 잡몹 소환, 자신은 회피 | `TARGET TYPE(소환사)` 우선순위 |
| 자폭형 | 접근 후 2틱 예고 뒤 폭발 | 예고 타일 회피, 사거리 밖 처리 |
| 치유형 | 아군 HP% 낮으면 회복 | `TARGET LOWEST_HP` 판단 오류 유발 |
| 보스 | 페이즈별 규칙표 교체 + 텔레그래프 | 플래그 활용 페이즈 대응 |

## 6. 아이템 재설계 (2축 분리)

### 6.1 스탯 접사 (생존 여유 제공, 성장 아님)
- `defense_flat`, `hp_max`, `regen_tick`, `attack_flat`
- **상승폭을 의도적으로 낮게 유지** (전 구간 20~30% 이내). 스탯으로 뭉개기 방지.

### 6.2 모듈 접사 (로직 능력 확장) — **신규, 핵심**

| 모듈 | 효과 |
|:--|:--|
| 확장 슬롯 | 규칙 슬롯 +1 |
| 연산 코어 | CPU 예산 +3 |
| 센서 | 특정 인지 변수 해금 (예: `대상이 시전 중인가`) |
| 서브루틴 | 플래그 +1개 |
| 액추에이터 | 특정 행동 해금 (예: `엄폐물 뒤로 이동`) |
| 예측 회로 | 텔레그래프를 1틱 더 일찍 인지 |

### 6.3 저주 접사 (트레이드오프)
- 예: `[과부하] 공격력 +40%, CPU 예산 -4`
- 강한 스탯을 얻는 대신 로직 정교함을 포기하는 선택지

### 6.4 스탯 연산 순서 (v1 모호성 수정)
```
최종 스탯 = (기본값 + 고정 합계) × (1 + 퍼센트 합계 / 100)
```

## 7. 밸런스 및 어뷰징 차단

v1 수식은 **"회복 타일 위에서 무한 대기 → 풀피로 처치"** 가 수학적 최적해였다. 아래로 차단한다.

| 문제 | 대응 |
|:--|:--|
| 회복 타일 무한 어뷰징 | 샘 잔여량(총 회복량) 도입 + 전투 중 `base_regen` 50% 감쇠 |
| 무한 카이팅 | 방 체류 40틱 초과 시 **추격자(Hunter) 스폰**, 이후 20틱마다 추가 |
| 층 지연 | 층 체류 틱에 비례해 적 공격력 스케일 (+1%/10틱) |
| 스탯 뭉개기 | 스탯 접사 상승폭 상한 고정, 적 능력치는 층 기준 고정 스케일 |
| 규칙 무한 증식 | CPU 예산 제약 |

### 회복 수식 (수정본)
```
regen_effective = (base_regen × 전투중 ? 0.5 : 1.0) + tile_regen
hp_new = min(hp_max, hp_current + regen_effective)
tile_pool -= tile_regen   # 0 이하 시 해당 타일 소멸
```

## 8. UX 설계 — **디버깅 화면이 이 게임의 메인 UI**

오토배틀은 플레이어 입력 공백 시간이 길다. 그 시간을 **"관찰과 진단"** 으로 채우지 못하면 게임이 지루해진다.

### 8.1 규칙 에디터
- 좌: 블록 팔레트 (인지/행동/셀렉터), 우: 우선순위 리스트 (드래그 정렬)
- **텍스트 뷰 토글** — 규칙표를 텍스트로 보고 직접 편집·복붙 가능
- 실시간 CPU 예산 게이지 표시

### 8.2 실행 로그 패널 (필수)
```
T027 | [3] 적거리(2) <= 사거리(3) → 공격 TARGET 고블린궁수  (dmg 14)
T028 | [1] HP%(18) < 20 AND 포션(0) > 0 → FALSE
       [2] HP%(18) < 30 AND 회복타일(있음) → 회복타일로 이동
```
- 매 틱 **평가된 조건의 실제 값**을 노출 → 오판단 원인 즉시 특정

### 8.3 사후 분석
- 사망 시 자동으로 **직전 15틱 리플레이** 재생
- 되감기 슬라이더, 규칙별 발동 횟수 통계, 피해 히트맵
